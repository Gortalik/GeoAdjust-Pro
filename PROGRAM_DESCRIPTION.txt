GeoAdjust Pro — ПОЛНОЕ ВНУТРЕННЕЕ ОПИСАНИЕ РАБОТЫ ПРОГРАММЫ
================================================================================
Версия описания: 2026-05-17
Структура проекта после наведения порядка:
- Корневая папка: только run_geoadjust_pro.py, pyproject.toml, .gitignore, PROGRAM_DESCRIPTION.txt
- GeoAdjustPro/src/geoadjust/ — основное приложение (GUI + ядро)

================================================================================
1. ЗАПУСК ПРОГРАММЫ ИЗ ОБОЛОЧКИ (SHELL)
================================================================================

1.1. Основная точка входа — run_geoadjust_pro.py (в корне)
   - Скрипт написан для Windows PowerShell / cmd.
   - Выполняет:
     1. Печатает красивый баннер с перечнем возможностей.
     2. Определяет путь к приложению: Path(__file__).parent / "GeoAdjustPro" / "src"
     3. Выполняет os.chdir(app_dir) — меняет текущую директорию.
     4. Запускает subprocess.run([sys.executable, "-m", "geoadjust"])
     5. Это эквивалентно команде: python -m geoadjust внутри папки GeoAdjustPro/src
   - Обработка KeyboardInterrupt и ошибок.

   Почему именно так:
   - Позволяет запускать приложение как обычный .exe без установки.
   - Все относительные пути внутри приложения работают корректно, потому что cwd = GeoAdjustPro/src.

1.2. Точка входа приложения — GeoAdjustPro/src/geoadjust/__main__.py
   - Проверка версии Python (≥ 3.8).
   - Проверка обязательных пакетов (numpy, scipy, PyQt5, chardet, networkx, pandas).
   - Настройка логирования:
       logging.basicConfig(level=logging.INFO, format='[%(asctime)s] %(levelname)s: %(name)s - %(message)s')
     Лог пишется и в консоль, и в файл geoadjust_debug.log.
   - Создание QApplication.
   - Создание конфигурации MainWindowConfig (Ribbon интерфейс по умолчанию).
   - Создание MainWindow.
   - Показ окна: main_window.show()
   - Запуск event loop: sys.exit(app.exec_())

================================================================================
2. АРХИТЕКТУРА ПРИЛОЖЕНИЯ (ВНУТРЕННЯЯ РАБОТА)
================================================================================

2.1. Модульная структура (GeoAdjustPro/src/geoadjust/)
   gui/          — весь пользовательский интерфейс (PyQt5)
   core/         — математическое ядро и обработка данных
   io/           — ввод/вывод, парсеры форматов, экспорт, сохранение проектов
   crs/          — системы координат, геоиды, преобразования
   api/          — публичный API (пока минимальный)

2.2. GUI слой (gui/)
   - main_window.py — главное окно, меню, Ribbon, dock-виджеты.
   - project_manager.py — работа с проектом в памяти (Point, Observation).
   - components/ — PlanView (графика сети), таблицы пунктов и измерений,
                   PropertiesWidget, HistoryWidget, LogWidget.
   - processing/ — ProcessingThread (QThread) — тяжёлые вычисления не блокируют UI.
   - dialogs/ — все диалоги импорта, редактирования, экспорта, настроек.

   Сигнально-слотовая архитектура:
   point_selected → _on_point_selected → PropertiesWidget.update()
   observation_selected → аналогично.

2.3. Ядро обработки (core/)
   - processing/pipeline.py — 9 этапов предобработки + уравнивание.
   - adjustment/ — engine.py (МНК), equations_builder.py, robust_methods.py
                   (Хьюбер, Тьюки, L1), weight_builder.py.
   - preprocessing/ — direction_processor, station_processor, tolerances.py
   - analysis/ — gross_errors.py, ellipse_errors.py, baarda_method.py
   - network/models.py — классы Point, Observation, Network.

   Математика:
   - Параметрическое уравнивание по методу Ю.И. Маркузе.
   - Решение нормальных уравнений через numpy.linalg или scipy.sparse.
   - Робастные итерации с пересчётом весов.

2.4. Ввод/вывод (io/)
   - formats/ — GSIParser, SDRParser, DATParser, POSParser и базовый BaseParser.
   - project/ — GAD-формат проекта (JSON + метаданные), ResultsSaver.
   - export/ — DXF, GOST-отчёт (HTML/RTF), DynAdjust.

2.5. Системы координат (crs/)
   - database.py — все СК РФ (СК-42, СК-95, ГСК-2011, МСК субъектов).
   - geoid.py — EGM2008, РусГеоид-2011.
   - transformer.py — 7-параметровое преобразование Гельмерта + проекция Гаусса-Крюгера.

3. КАК ВЫПОЛНЯЮТСЯ РАБОТЫ В ОБОЛОЧКЕ (SHELL / ТЕСТЫ)
================================================================================

3.1. Запуск тестов и скриптов из корня
   Почти все файлы в tests/ и scripts/ используют один и тот же приём:

   import sys
   from pathlib import Path
   sys.path.insert(0, str(Path(__file__).parent / 'GeoAdjustPro' / 'src'))

   Это позволяет импортировать пакет geoadjust напрямую, как будто он установлен.

3.2. Типичный сценарий теста (пример test_full_flow.py, test_gui.py)
   1. Создаётся QApplication (если ещё нет).
   2. ProjectManager создаёт временный проект.
   3. В проект добавляются тестовые пункты и измерения.
   4. Создаётся MainWindow с текущим проектом.
   5. Вызывается main_window._refresh_data_views()
   6. Имитируются сигналы (point_selected.emit, observation_selected.emit).
   7. Проверяется, что PropertiesWidget, таблицы и графика обновились.
   8. Иногда запускается ProcessingThread и ждётся сигнал finished.

3.3. Работа с реальными данными (test_real_mes/)
   - Скрипты в scripts/ (analyze_all_real_data.py и т.д.) проходят по папкам
     test_real_mes/s_b/, s_b2/, gnss/ и т.д.
   - Для каждого файла вызывается соответствующий парсер:
       GSIParser().parse(path)
       SDRParser().parse(path)
   - Результаты сохраняются в output/ в виде текстовых ведомостей и HTML-отчётов.

3.4. Headless-режим (без GUI)
   - Многие тесты создают QApplication, но не вызывают app.exec_().
   - Это позволяет проверять логику без открытия окон.
   - Для визуальных тестов иногда используется QTest.mouseClick и т.д.

3.5. Логирование и отладка
   - Все важные действия пишутся через logging.getLogger(__name__)
   - Логи дублируются в файл geoadjust_debug.log в корне GeoAdjustPro/src
   - В shell-скриптах часто перенаправляют вывод: python script.py > log.txt 2>&1

================================================================================
4. ЖИЗНЕННЫЙ ЦИКЛ ОБРАБОТКИ ГЕОДЕЗИЧЕСКИХ ДАННЫХ
================================================================================

1. Создание проекта (GUI или программно)
2. Импорт данных (меню «Импорт» → выбор формата)
3. Автоматическая предобработка (9 этапов):
   - контроль допусков
   - поиск грубых ошибок (стандартизованные остатки, трассировка ходов)
4. Уравнивание (МНК + робастные методы)
5. Анализ надёжности (метод Баарда, внутреняя/внешняя надёжность)
6. Построение эллипсов ошибок
7. Генерация отчётов (ГОСТ 7.32-2017, ведомости координат, превышений, точности)
8. Экспорт (DXF, DOCX, HTML, PDF)

Все этапы выполняются в отдельных потоках (ProcessingThread),
а прогресс отображается в ProgressDialog.
